# CloudBooter for Cloudflare

Provisions a small Workers Free-plan baseline (Worker, KV, R2, D1) and writes Terraform you can inspect before applying.

Cloudflare is edge / serverless here — no VPC, VM, or SSH. The workflow still matches the other providers: auth → inventory → validate → generate → optional apply.

## Quick start

```bash
export CLOUDFLARE_API_TOKEN="..."
export CLOUDFLARE_ACCOUNT_ID="..."
cd cloud/Cloudflare
./setup_cloudflare_terraform.sh
```

Windows: `.\setup_cloudflare_terraform.ps1`

See [docs/QUICKSTART.md](docs/QUICKSTART.md) and [USAGE.md](USAGE.md).

## What the default creates

| Resource | Terraform type | Free plan? |
|---|---|---|
| Worker + workers.dev route | `cloudflare_workers_script` + subdomain | Yes |
| KV namespace | `cloudflare_workers_kv_namespace` | Yes |
| R2 bucket (Standard) | `cloudflare_r2_bucket` | Yes |
| D1 database | `cloudflare_d1_database` | Yes |

Pages, Queues, Durable Objects, DNS zones, and Workers AI are documented as later options — not generated by default.

## Guardrails

1. Bash / PowerShell constants before generation
2. Python `CloudflareFreeTierLimits` for the CLI and tests
3. Terraform `check` blocks at plan / apply

Override only with `CLOUDFLARE_ALLOW_PAID_RESOURCES=true`. Limits: [docs/FREE_TIER_LIMITS.md](docs/FREE_TIER_LIMITS.md).
